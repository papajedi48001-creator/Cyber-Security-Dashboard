# Backup Evidence Runbook

Portal เก็บ **หลักฐาน** ว่างานสำรองข้อมูลทำงานหรือไม่ ไม่ได้สั่ง backup, restore หรือลบข้อมูลเอง ปุ่มเหล่านี้จะไม่มีใน Portal งานจริงทำในระบบ backup ตามขั้นตอนของระบบนั้น

> Backup สำเร็จ ไม่ได้แปลว่ากู้คืนได้ สถานะ "ยืนยันการกู้คืน" จะขึ้นเมื่อมีผลทดสอบกู้คืนที่ผ่านภายใน 90 วันเท่านั้น

## บทบาท

| งาน | ผู้ทำ |
|---|---|
| เพิ่มงาน backup (ชื่อ, รอบที่คาดไว้, ปลายทาง) | Security Administrator |
| บันทึกผล backup และผลทดสอบกู้คืน | Security Administrator, Security Operator |
| ดูสรุป (จำนวนเท่านั้น) | Executive Viewer ผ่านหน้า Executive |

## บันทึกผลประจำวัน

1. เปิดหน้า Backup ใน Portal
2. บันทึกผลจากรายงานของระบบ backup ทีละงาน หรือนำเข้า CSV ที่ส่งออกจากระบบ backup รูปแบบ
   `job,result,completed_at,size_bytes,encrypted,retention_until` (เวลาเป็น UTC แบบ ISO 8601)
3. ตรวจสถานะแต่ละงาน
   - **สำรองตามรอบ**: ผลล่าสุดสำเร็จ อยู่ในรอบที่คาดไว้ และเข้ารหัส
   - **ล้มเหลว**: ผลล่าสุดล้มเหลว แสดงจำนวนครั้งที่ล้มเหลวติดกัน
   - **ขาดรอบ**: ไม่มีผลสำเร็จภายในรอบที่คาดไว้
   - **ไม่ได้เข้ารหัส**: ผลล่าสุดไม่ได้เข้ารหัสก่อนส่ง GDCC
   - **ไม่มีข้อมูล**: ยังไม่เคยบันทึกผล ห้ามตีความว่าปกติ

## เมื่อพบปัญหา

1. งานใดล้มเหลว ขาดรอบ หรือไม่เข้ารหัส ให้เปิด incident ระดับ P3 (หรือ P2 ถ้าเป็นระบบสำคัญ เช่น HIS) และแนบชื่องานในหัวข้อ
2. แก้ไขในระบบ backup แล้วบันทึกผลรอบถัดไปใน Portal
3. ปิด incident ด้วย Closure Evidence ที่อ้างอิงรายงานของรอบที่สำเร็จ

## ทดสอบกู้คืน

1. ทดสอบกู้คืนตามรอบที่โรงพยาบาลกำหนด (ไม่เกินทุก 90 วันต่องาน) บนเครื่องทดสอบเท่านั้น ห้ามกู้ทับระบบจริง
2. บันทึกในหน้า Backup: งาน, เวลาทดสอบ, ผล (กู้คืนได้ หรือ กู้คืนไม่ได้) และที่เก็บหลักฐาน
3. ห้ามแนบข้อมูลผู้ป่วยเป็นหลักฐาน ใช้รายงานผลการตรวจ (จำนวนตาราง, checksum, เวลาที่ใช้) แทน
