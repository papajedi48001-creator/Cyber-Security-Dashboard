# SIEM Capacity Baseline

วัดจาก Existing SIEM Server ก่อน rebuild เป็น Wazuh all-in-one ห้ามบันทึก secret หรือข้อมูลผู้ป่วย

## ฮาร์ดแวร์ที่วัดได้

| รายการ | ค่าที่วัดได้ | วิธีวัด / วันที่ |

| CPU (จำนวน core, รุ่น) | | |
| RAM | | |

| ชนิด disk (SSD/HDD, RAID) | | |

## ปริมาณ log

| รายการ | ค่าที่วัดได้ | ช่วงเวลาที่วัด |
|---|---|---|
| จำนวน log source | | |
| EPS เฉลี่ย (Sophos) | | |
| EPS สูงสุด (Sophos) | | |
| ขนาด log ต่อวัน (GB) | | |
| ประมาณการพื้นที่ 90 วัน (hot) | | |
| ประมาณการพื้นที่ 1 ปี (archive, หลังบีบอัด) | | |

ประมาณการพื้นที่ hot = ขนาดต่อวัน × 90 × 1.3 (index overhead และ replica 0) ให้บันทึกสูตรที่ใช้จริงไว้ด้วย

## เทียบกับขั้นต่ำของ Wazuh all-in-one

ใช้ค่าจากเอกสารทางการของ Wazuh รุ่นที่จะติดตั้ง ณ วันที่วัด แล้วกรอกผลเทียบ

| รายการ | ขั้นต่ำที่ใช้ตัดสิน | ค่าจริง | ผ่าน |
|---|---|---|---|
| CPU | ≥ 8 vCPU | | ☐ |
| RAM | ≥ 16 GB | | ☐ |
| Disk ว่างสำหรับ 90 วัน | ≥ ประมาณการ hot × 1.25 | | ☐ |

## เกณฑ์ขยาย (scale-out threshold)

เมื่อถึงเกณฑ์ใดเกณฑ์หนึ่งต่อเนื่อง 7 วัน ให้เสนอแยก indexer ออกเป็นเครื่องที่สอง (ADR 0003)

| ตัวชี้วัด | เกณฑ์ |
|---|---|
| EPS เฉลี่ยต่อวัน | > 70% ของ EPS ที่ทดสอบผ่านแล้ว |
| Disk ของ indexer | > 75% |
| `events_dropped` ของ wazuh-analysisd | > 0 |
| Heap ของ indexer | > 85% ต่อเนื่อง |
