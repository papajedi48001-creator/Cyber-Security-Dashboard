# Portal Integration UAT (แผน 3)

บันทึกผลการทดสอบการเชื่อมต่อของ Portal กับโมดูลทั้งหมด ใช้ข้อมูลสังเคราะห์เท่านั้น ห้ามใช้ข้อมูลผู้ป่วยหรือข้อมูลจริงของโรงพยาบาล

เอกสารนี้เป็นหลักฐานประกอบการพิจารณา **ไม่ใช่การอนุมัติให้ติดตั้งใช้งานจริง** การติดตั้งบนเครื่องจริงต้องได้รับอนุมัติจากโรงพยาบาลก่อน

## สภาพแวดล้อมทดสอบ

- Portal build แบบ production (`next build`, standalone) บนฐานข้อมูล MariaDB สำหรับทดสอบ
- ผู้ใช้ทดสอบ 4 บทบาท: Security Administrator, Security Operator 2 คน, Executive Viewer (สร้างโดย `portal/e2e/auth.setup.ts`)
- Wazuh, LINE, SMTP และ Cloudflare เป็นข้อมูลจำลอง ไม่ได้เชื่อมต่อระบบจริง
- รันอัตโนมัติทุกครั้งใน CI (`npx playwright test`) ทดสอบหลักอยู่ที่ `portal/e2e/operations-flow.spec.ts`

## ความเสี่ยงที่ยังเปิดอยู่

- ปฏิทินเวลาทำการและวันหยุดยังเป็นค่าตั้งต้น รอโรงพยาบาลยืนยัน (มีผลต่อ SLA และเวลาส่งแจ้งเตือน P3/P4)
- Duo ตรวจด้วยมือ ช่วงระหว่างรอบตรวจไม่มีการเฝ้าระวัง
- Cloudflare แผน Free เป็นข้อมูลสุ่มตัวอย่าง ใช้เป็นหลักฐานว่าไม่มีการโจมตีไม่ได้
- ผลสแกนพอร์ตต้องนำเข้าด้วยมือ ถ้าไม่นำเข้าเกิน 36 ชั่วโมง สถานะเป็น "ไม่ทราบ"
- FortiSIEM ยังทำงานตามเดิม (ADR 0008) การปลด FortiSIEM ในอนาคตเป็นการตัดสินใจแยกของโรงพยาบาล

## ข้อเสนอ

ผลทดสอบอัตโนมัติผ่านครบ แนะนำให้ทำ UAT ร่วมกับโรงพยาบาลตามตารางข้างบนก่อนขออนุมัติเปิดใช้งานจริง ยังไม่แนะนำให้เปิดใช้งานจริงจนกว่า UAT ร่วมจะผ่าน
